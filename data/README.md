# Synthetic starter kit (NOT official Samsung data)

Everything in this folder is **synthetic**. The official Theme 2 starter kit was not available,
so it was generated by `scripts/make_synthetic_kit.py` (seed 2026) from general knowledge of
Galaxy One UI Settings menus and common troubleshooting advice. No text was copied from Samsung
websites. Every JSON file carries `"metadata": {"synthetic": true, ...}`.

| File | Contents |
|---|---|
| `schema.py` | Pydantic output contract (from the brief, Appendix A) — the single source of truth |
| `deeplinks.json` | 153 masked Settings deeplinks (`bixby://masked/act/<random token>`), parents and child screens, control types, validation keys |
| `siis_responses.json` | 60 customer-care style troubleshooting articles (plain text, no URLs), mixing auto / manual / critical steps |
| `queries.json` | 106 user complaints (Battery, Display, Camera, Performance + Connectivity, Navigation, Sound…) incl. 10 multi-symptom and 10 expected `no_match` |
| `paraphrases_heldout.json` | 101 unseen paraphrases of 32 queries + 12 unseen negatives; **cache benchmarking only, never pre-warmed** |
| `samples/` | 5 gold input → output pairs in the API response format |

Deliberate test properties:
* Tokens are random, so deeplinks can only be matched on `description` / `message` / `cna_description`.
* Parent menus (`Display`) and their child screens (`Display › Navigation bar`) both exist.
* Three screens mentioned in SIIS text are intentionally missing from the catalog
  (`Display › Touch sensitivity`, `Advanced features › Motions and gestures`,
  `Accessibility › Interaction and dexterity`) to exercise `bixby://dummy_positive`.

## Swapping in the official kit
Drop the official files into this folder with the same names. Only `app/data_loader.py`
knows the raw formats; adjust field names there if they differ. Regenerate with
`python scripts/make_synthetic_kit.py` (it overwrites these files).
