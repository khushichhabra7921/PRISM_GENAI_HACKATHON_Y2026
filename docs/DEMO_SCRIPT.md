# Demo video script (≤ 5 minutes, official kit)

The video, [demo/SGTE_demo.mp4](demo/SGTE_demo.mp4), is generated by `scripts/make_demo_video.py` (narration text:
[demo/narration.txt](demo/narration.txt), subtitles: [demo/SGTE_demo.srt](demo/SGTE_demo.srt)). The script starts its
own engine with an **empty cache and no pre-warm**, so the first request for a complaint is genuinely cold and the
repeat is a genuine cache hit; the latencies it narrates are read off the page during the recording. The run of show
below is for recording a live version by hand.

Everything here is free: the prototype runs locally, and the video can be recorded with tools built into
Windows 11 and uploaded to YouTube (as *Unlisted*) or Google Drive (*Anyone with the link can view*).

## Regenerate the deck and the video

```bash
.venv/Scripts/pip install -r requirements-video.txt
```

The deck needs the API running on port 8000 (it takes two live screenshots of `/demo` for slide 11):

```bash
.venv/Scripts/python scripts/make_deck.py
```

The video starts its own engine on port 8010 and renders slides 2 and 4 from the refreshed deck:

```bash
.venv/Scripts/python scripts/make_demo_video.py
```

## Before recording by hand

1. Start the stack and wait until it is healthy:
   ```bash
   docker compose up --build
   ```
   ```bash
   curl -s localhost:8000/health
   ```
   (Without Docker: `.venv/Scripts/python -m uvicorn app.main:app --port 8000`; set `SGTE_PREWARM=0` and a fresh
   `SGTE_CACHE_DIR` to show the cold path first.)
2. Open `http://localhost:8000/demo` in a browser, full screen (F11), zoom about 110%.
3. Record with **Snipping Tool → Record** (Win + Shift + R) or **Xbox Game Bar** (Win + Alt + R).
   Trim in **Clipchamp** (free, preinstalled on Windows 11) if needed.

## Run of show

| Time | Show | Say (key points) |
|---|---|---|
| 0:00–0:20 | Title card | Team Nexora, Theme 2: a TechCorp Nexa complaint + its SIIS article → validated, ordered, one-tap plan. |
| 0:20–0:45 | Deck slide 2 (problem) | Symptoms vs menus; official kit = 20 complaints, each with its SIIS article `{title, content}`; answer in the `sample_output.json` shape; targets < 300 ms / < 8 s / 0 invented steps / 0 invalid deeplinks. |
| 0:45–1:15 | Deck slide 4 (architecture) | The article is the only source of steps: sections, relevant blocks, canonical steps; ordering; one deeplink per navigation; 11 validators. |
| 1:15–2:05 | Demo picker → **row_21** *"screen inputs are delayed and the touch is laggy"* → **Send with SIIS** | Cold request (~1–1.5 s): numbered touchscreen procedure kept whole, 11 actions; **Open ›** on *Turn On Touch Sensitivity* shows the Display deeplink; safe mode and factory reset last. |
| 2:05–2:35 | Send **row_21** again, then the raw JSON panel | Payload-scoped cache hit (~30 ms, 0 LLM calls); a plan from another article is never served. `?view=contract` = exactly the sample-output shape. |
| 2:35–3:15 | **row_8** *"main screen stays small"* (screen-mirroring guide) → **Why these steps?** | One action (change the aspect ratio): 1 of 20 instruction blocks kept, every block's relevance score in the evidence trail. |
| 3:15–3:35 | **row_1** (email screen goes blank) | *Clear the Email App's Cache and Data*: two navigations → two step groups, each with its own deeplink. |
| 3:35–4:05 | Type *"the screen does not rotate when I turn the tablet"*, then *"my Nexa watch wont sync my steps"* | Free text: the engine retrieves the rotation article itself. No coverage → `contexts: []` + `fallback: no_match`, logged for the content team. |
| 4:05–4:35 | Results card | 20/20 schema-valid, 100% rule checks, every step found in its article, P95 repeat / cold; synthetic regression kit gold accuracy and paraphrase hit rate; test count. |
| 4:35–5:00 | Limitations card | No official catalog (synthetic, official scheme, one real entry), no gold plans for the official complaints, relevance heuristic, local SLM off the request path. |

## After recording

1. Upload to YouTube (visibility **Unlisted**) or Google Drive (share: *Anyone with the link*).
2. Put the link in `README.md` (the "Demo video" row of the Submission table), then refresh the deck so slides 5 and
   11 carry it: `python scripts/make_deck.py --video-url <link>`; upload the deck where the README's Presentation
   link points.
3. Commit, then move the release tag to that final commit (see the README's *Release* section).
